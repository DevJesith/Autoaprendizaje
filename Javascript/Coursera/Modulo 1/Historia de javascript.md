Mejoras de JavaScript
En esta lectura, aprenderá sobre la historia de JavaScript y la importancia de ECMA (Asociación Europea de Fabricantes de Computadoras) y ECMAScript.  

JavaScript es un lenguaje de programación que tuvo comienzos humildes.

Fue creado en tan solo 10 días en 1995 por una sola persona, Brendan Eich, a quien se le encargó crear un lenguaje de programación simple para ser utilizado en la versión 2 del navegador Netscape. Inicialmente se llamó LiveScript, pero como el lenguaje Java era tan popular en ese momento, el nombre se cambió a JavaScript, aunque Java y JavaScript no están relacionados de ninguna manera.

Durante los primeros años, después de su creación, JavaScript era un lenguaje de programación sencillo para añadir efectos de desplazamiento del ratón y otras interactividades. Esos efectos se añadían a las páginas web mediante el  elemento HTML <script>  .

Dentro de cada uno de los elementos del script, podría haber algún código JavaScript. Debido a la regla de que HTML, CSS y JavaScript deben ser compatibles con versiones anteriores, incluso el código más avanzado escrito en JavaScript en la actualidad termina escribiéndose entre esas etiquetas de script.

Con el paso de los años, JavaScript se volvió cada vez más poderoso y, en los últimos tiempos, se lo promociona continuamente como uno de los tres lenguajes más utilizados.

En 1996, Netscape llegó a un acuerdo con la organización conocida como ECMA (Asociación Europea de Fabricantes de Computadoras) para redactar la especificación del lenguaje JavaScript, y en 1997 se publicó la primera edición de la especificación ECMAScript.

La ECMA publica esta especificación como el estándar ECMA-262.

Se puede pensar en un estándar como una manera acordada de cómo deberían funcionar las cosas. Por lo tanto, ECMA-262 es un estándar que especifica cómo debería funcionar el lenguaje JavaScript.

Ha habido 12 actualizaciones de ECMA-262: la primera fue en 1997.

JavaScript como lenguaje no es una entidad completamente independiente y autónoma. Solo existe como una implementación. Esta implementación se conoce como motor de JavaScript.

Tradicionalmente, el único entorno en el que era posible ejecutar un motor de JavaScript era el navegador. Más específicamente, un motor de JavaScript era simplemente otro componente del navegador. Su función era ayudar al navegador a cumplir el objetivo de sus usuarios de utilizar Internet para trabajar, investigar y jugar.

Por lo tanto, cuando los desarrolladores escriben código JavaScript, lo utilizan para interactuar con un motor JavaScript. En otras palabras, los desarrolladores escriben código JavaScript para poder "hablar" con un motor JavaScript.

Además, el propio motor de JavaScript ofrece distintas formas de interactuar con otras partes del navegador, conocidas como API del navegador.

Por lo tanto, el código que escribe en el lenguaje de programación JavaScript le permite: 1. Interactuar con el motor de JavaScript dentro del navegador 2. Interactuar con otras funcionalidades del navegador que existen fuera del motor de JavaScript, pero que aún están dentro del navegador.

Aunque tradicionalmente era posible interactuar con el motor JavaScript sólo dentro del navegador, todo esto cambió en 2009, cuando Ryan Dahl creó Node.js.

Se le ocurrió una forma de utilizar un motor de JavaScript como una entidad independiente. De repente, era posible utilizar JavaScript fuera del navegador, como un programa independiente en la línea de comandos o como un entorno del lado del servidor.

Hoy en día, JavaScript es omnipresente y se ejecuta en navegadores, en servidores y, en realidad, en cualquier dispositivo que pueda ejecutar un motor JavaScript.
